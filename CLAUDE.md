# nutrition-rag

Evidence-ranked RAG over nutrition research for diabetes prevention, weight
management and maternal nutrition, with Indian / South Asian users in mind.
The goal is ML discipline applied to RAG: a measured corpus, an eval set from
the start, ablations and failure analysis. Every component must justify itself
with numbers.

## Status

Built in phases; stop after each phase for review. Phase 0 (setup + port of
the legacy ingester) is done. Phase 1 (dataset ingestion) is next.

## Commands

```bash
make setup     # create .venv and install the package with dev extras
make test      # pytest, offline tests only (-m "not network")
make ingest ARGS="--max-per-topic 50"    # PubMed ingest (needs NCBI_EMAIL)
.venv/bin/nrag --help
```

`nrag ingest` options: `--since YYYY/MM/DD`, `--max-per-topic N`,
`--topic NAME` (repeatable), `--strong-only`, `--config PATH`.

## Layout

- `config.yaml`: every tunable number (queries, design rules, weights, thresholds, TTLs). Never hardcode these.
- `src/nrag/config.py`: `load_config()` (honours `NRAG_CONFIG`), `resolve_path()`, `env()` for secrets.
- `src/nrag/net.py`: `CachedHttp`, a rate-limited, retrying client with an on-disk cache under `data/cache/`. **All network calls go through it.** Cache keys and files exclude `api_key`/`email`/`tool`/`mailto`.
- `src/nrag/ingest/pubmed.py`: `Rules.from_config`, `parse_articles`, `classify_design`, `extract_sample_size`, `score`, `exclusion_reason`, `PubMedClient` (esearch → PMID list, efetch by POSTed ID batches), `ingest()`.
- `src/nrag/cli.py`: typer app. Commands for later phases are stubs that exit with code 2.
- `legacy/ingest_pubmed.py`: the original script, kept unchanged as the reference for `tests/test_parity.py`.
- `tests/fixtures/pubmed/`: **synthetic** PubMed XML (fake PMIDs 900000xx), generated by `make_fixtures.py` in the same folder.

## Conventions

- Secrets only via env / `.env` (gitignored; see `.env.example`). Never print them.
- Cache every network and LLM call; responses are keyed by their exact inputs.
- NCBI: send `tool` + `email`; 0.34 s spacing without a key, 0.11 s with one.
- Records are flagged, not silently dropped; drops go to an excluded file with a reason.
- Every module has pytest tests; a phase isn't done until `make test` passes.
- Don't invent data or metrics. If something can't run here, say so and give the command.
- Commit at the end of each phase.

## Parity with the legacy script

Phase 0 reproduces `legacy/ingest_pubmed.py` exactly: end-to-end outputs,
per-record parsing and classification, and grid tests over the
exclusion and scoring functions. Changing a config value that alters legacy
behaviour makes `tests/test_parity.py` fail. That's intended. When Phase 1
deliberately changes behaviour, update or retire the affected parity
assertions in the same commit and record the before/after corpus counts.

## Known legacy issues (to fix in Phase 1)

1. PubMed returns at most 10k IDs per search, so searches must be split by year.
2. Retractions are only rechecked when a record is fetched again (`--since` refreshes miss them). Needs a full-corpus recheck plus Crossref.
3. `medline_indexed` uses citation status, not journal indexing. Use the NLM Catalog.
4. The text design fallback matches the term anywhere in the abstract (e.g. "previous meta-analyses" → meta_analysis).
5. Existing records are never refreshed when fetched again (MeSH, expressions of concern).
6. Design labels: `Multicenter Study` counts as a design; `Observational Study` is matched before cohort MeSH.
7. Sample sizes 1900–2100 are skipped as years; `excluded.jsonl` is appended without dedup.
